# Supporting more languages

*Turning the German-only helper into a language-parameterised one: the same word
contract, renderer and recipe, working for the languages ARASAAC covers well —
with German as one instance, not the rule.*

## 1. Goal and problem

Today everything is German: the catalog loads only `metadata_de.json`
([`arasaac_mcp/catalog.py:154`](../arasaac_mcp/catalog.py)), the MCP tool texts
and the recipe tell the model to search and reply in German, and the fixtures
ship a German synthetic index. The architecture is not German — the **word
contract** (`Catalog.search/resolve/label_of`) is language-neutral by
construction — but the data file name, the prose and the generation pipeline
bake German in.

**Goal:** one code path; the language becomes a *per-request parameter*.
A request in (or addressed to) any supported language searches, labels and
renders in that language, while the invariants of
[`icon-descriptions.md`](icon-descriptions.md) §5 — word-only addressing, label
round-trip, AND search — hold **in every language**.

## 2. Ground truth (what makes this feasible)

| Fact | Consequence |
| --- | --- |
| Pictogram PNGs are language-independent: the static URL is `{base}/{id}/{id}_{size}.png` ([`fetch.py:24`](../arasaac_mcp/fetch.py)) — no language component | Images never change with language; only the word index does |
| ARASAAC metadata is per language: `https://api.arasaac.org/v1/pictograms/all/<lang>`; [`scripts/download_icons.py:62`](../scripts/download_icons.py) already supports `--lang` | Index acquisition for any locale is trivial |
| PNG filenames embed the language's first keyword (`2339_Auto.png` vs `2339_car.png`, via `_synthesize_file`/`_slug`, [`catalog.py:108-125`](../arasaac_mcp/catalog.py)) | Each language needs `metadata_<lang>.json` and its own filename synthesis; a same-`pic_id` fallback bridges missing files |
| `synsets` (WordNet IDs, e.g. `02209508-n`) are in the metadata for ~12.5k of ~13.8k pictograms | A ready-made language-independent identification bridge (see §5, Phase E) |
| Coverage varies: ~12 languages are well covered (de, en, es, fr, it, pt, nl, pl, ru, ca, gl, eu); many other locale codes are sparse or empty | First-class support is scoped to the well-covered set; anything else fails loudly rather than badly |

**Key simplification:** because the bulk-downloaded PNG set is
language-independent, a new language needs only its `metadata_<lang>.json`
(~a few MB) — no second PNG download. The existing icons serve all languages.

## 4. Design decisions

Locked:

1. **Language is a per-request parameter.** Tools get an optional `lang`
   parameter (default `"de"`, so existing callers stay valid); the agent infers
   it from the user's input. `Catalog(lang)` / `get_catalog(lang)` with a lazy
   per-language index cache. No runtime-wide language setting.
2. **First-class languages: the 12 well-covered ones** — de, en, es, fr, it,
   pt, nl, pl, ru, ca, gl, eu. The architecture stays generic (any locale code
   ARASAAC serves), but only these are downloaded, tested and documented.
   Unknown codes are rejected with the supported list.
3. **Replies in the user's input language.** The recipe §0 rule becomes
   "mirror the user": conversational replies, `sentence`, `meaning`, `notes`
   and labels follow the user's language; the pictogram *keywords* follow the
   catalog language passed as `lang`.
4. **Language-specific filenames with a same-`pic_id` fallback.** `path_of`
   tries the language-synthesized filename, then the same id under any other
   present `metadata_*.json`, then the on-demand fetch (already
   language-neutral). With `ARASAAC_FETCH=off` a missing icon still fails
   instead of rendering a wrong pictogram.

## 5. Plan

### Phase A — Language-aware catalog

`Catalog(lang)`; `metadata_de.json` → `metadata_<lang>.json`;
`get_catalog(lang)` with a per-language cache. `path_of` gains the
same-`pic_id` cross-language fallback (§4.4). Search/resolve/label logic is
untouched — the data changes, the mechanism already is language-neutral.

- Files: `arasaac_mcp/catalog.py`.
- Tests: index building with `metadata_en.json` (the test
  [`icon-descriptions.md`](icon-descriptions.md) Phase 6 already asked for);
  filename synthesis and label round-trip per language; `path_of` fallback.

### Phase B — MCP layer

`ServerContext` holds a per-language catalog loader instead of one catalog.
Tools take `lang` (validated against the supported set). All German-baked
texts are reworded: instructions, tool docstrings, prompt, fallback rules —
"reply in the user's language, search in the request's language". Delivery
(URL in the text block, no `structuredContent`) is untouched.

- Files: `arasaac_mcp/mcp/context.py`, `server.py`, `instructions.py`,
  `search_pictograms.py`, `view_pictogram.py`, `render_pictogram_sheet.py`,
  `render_pictogram_layout.py`, `resources.py`, `arasaac_mcp/skill.py`.
- Tests: tool calls with `lang="en"` resolve and round-trip; unknown `lang`
  rejected with the supported list.

### Phase C — Recipe and skill (edit `prompt.md` only, regenerate)

§0 becomes "Language: mirror the user" (decisions §4.3); §3 wording generalises
("words in the selected language"); §5 role examples marked as examples; §6
reduction and §7 traps marked as German-specific tables, extensible per
language; §11/§13 prose rules follow §0. `SKILL_DESCRIPTION` becomes
language-neutral ("Turn text (de, en, es, fr, …) into ARASAAC pictograms").
Then `scripts/build_skill.py` regenerates `skills/arasaac/SKILL.md` and
`arasaac_mcp/recipe/`; `--check` must pass.

- Files: `scripts/prompt.md`, `scripts/build_skill.py` (description + LAYOUT
  map only if section names change).
- Tests: the German assertions above become language-neutral ones.

### Phase D — Language data acquisition

`download_icons.py --lang` accepts multiple languages (default stays `de`);
a metadata-only pass fetches the other 11 JSONs (no PNG downloads). Which
metadata files are tracked in git is decided during implementation: de stays
tracked; en probably too; the rest live in `ARASAAC_ICONS_DIR` on demand
(9 MB × 12 tracked files is too heavy).

- Files: `scripts/download_icons.py`, `.gitignore` (pattern for
  `metadata_*.json` beyond the tracked set).
- Tests: multi-language download smoke (file-based API override like the
  existing tests).

### Phase E — Synset bridge (language-independent identification)

Follows [`icon-descriptions.md`](icon-descriptions.md) Phase 1: extend
`Pictogram` with `synsets`. Then a word in language A finds candidates in
language B via shared WordNet synsets — as a fallback when the direct search
in the requested language yields nothing (sparse languages: gl, eu, nl have
1–4k untranslated terms), and for mixed requests ("label the German sheet in
Polish"). Lexical search stays primary; synsets are the bridge, not the index.

- Files: `arasaac_mcp/catalog.py` (fields + a `bridge`/lookup helper), MCP
  search tool (fallback only).
- Tests: A→B lookup over synthetic metadata with shared synsets; no behavioural
  change when synsets are absent.

### Phase F — Renderer

Attribution footer: keep one neutral footer ("Pictograms: ARASAAC (CC
BY-NC-SA)") or localise per reply language — decided when Phase F starts.
Fonts are already sufficient (Latin + Cyrillic); non-Latin scripts (e.g. zh)
would need additional Noto fonts and are out of scope until a language
requiring them becomes first-class.

- Files: `arasaac_mcp/layout.py` (footer only).

### Phase G — Tests and docs

Parameterize the fixtures (`helpers.py`, `conftest.py`), per-language
integration queries, language-neutral recipe assertions; update
[`AGENTS.md`](../AGENTS.md) (env/table), [`README.md`](../README.md) and the
invariants here (§6). Evaluation ([`icon-descriptions.md`](icon-descriptions.md)
§6) gains one German set (already exists) and one English set.

## 6. Invariants (must hold in every language)

- The model sees **only words** — no ids or filenames.
- Every shown label resolves back to the same pictogram.
- Search stays **AND** across query tokens; `resolve` prefers the plain label.
- `catalog.py` stays Pillow-free; the network happens only in `ensure`/`fetch.py`.
- A metadata-only index resolves (fetch or explicit failure — never a wrong icon).
- The public API (`Catalog.search/resolve/ensure`, MCP tools) stays backward
  compatible (`lang` defaults to `de`).

## 7. Scope split

- **PR 1 (core):** Phases A + B + C + G, end-to-end for **de + en**.
- **PR 2:** Phase D — the 11 additional metadata files + smoke tests.
- **Later:** Phase E (synset bridge), per-language overrides and stemming
  ([`icon-descriptions.md`](icon-descriptions.md) Phases 2–3, 5), footer
  localisation (Phase F), further languages by configuration only.
